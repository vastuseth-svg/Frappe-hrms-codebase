## Salary Days

| Case No. | Salary Calculation Method | Staff Calculation | Worker Calculation | Formula / Logic | Example |
| --- | --- | --- | --- | --- | --- |
| 1 | Worker Fixed 26 Days | Month Days (28/30/31) | Fixed 26 Days | Staff = Gross ÷ Month Days × Payable Days, Worker = Gross ÷ 26 × Payable Days | Staff: 31 Days, Worker: 26 Days |
| 2 | Month Days Calculation | Month Days | Month Days | Gross ÷ 28/30/31 × Payable Days | Both same |
| 3 | Month Days - Weekly Off | Month Days | Month Days - Weekly Off | Worker Payable = Month Days − Weekly Off | 31−5=26, 30−4=26 |
| 4 | Fixed 30 Days | Fixed 30 | Fixed 30 | Gross ÷ 30 × Payable Days | Every Month |
| 5 | Hour Based Worker | Month Days | Total Hours ÷ 8 | Above 26 Days = OT | 224 Hours = 28 Days |
| 6 | Attendance Based | Actual Present Days | Actual Present Days | Gross ÷ Base Days × Present | Present Only |
| 7 | Paid Weekly Off | Attendance + WO | Attendance + WO | Weekly Off Paid | 26 Present + 4 WO = 30 |
| 8 | Unpaid Weekly Off | Attendance | Attendance | WO Not Paid | Present Only |
| 9 | Paid Leave | Present + Paid Leave | Present + Paid Leave | CL/SL/EL Included | 24+2 Leave |
| 10 | Half Day | Half Day = 0.5 | Half Day = 0.5 | 2 Half = 1 Day | 25 + 2HD =26 |
| 11 | Sandwich Leave | Sandwich Rule | Sandwich Rule | WO between Leave counted | Fri Leave + Sun + Mon Leave |
| 12 | CTC Based | Annual CTC ÷12÷30 | Annual CTC ÷12÷30 | Fixed 30 | Monthly Salary |
| 13 | OT Calculation | OT on Hours | OT on Hours | Gross÷26÷8×OT×Rate | Double OT |
| 14 | Shift Based | Shift Wise | Shift Wise | Day/Night Shift Rate | Night Allowance |
| 15 | Minimum Guarantee | Minimum Pay Days | Minimum Pay Days | Company Minimum Days | Minimum 26 Days |

## Attendance Capture Modes

HRMS shall support multiple attendance capture channels. All channels feed the same attendance rule engine and payroll cycle.

| Mode | Device | Primary Users | Identification Method | Typical Use |
| --- | --- | --- | --- | --- |
| Employee Mobile App | Personal Android / iOS | Staff, Worker | Login + GPS / Selfie / Face | Field, remote, individual punch |
| Web Portal | Browser | Staff, Worker | Login + manual punch | Office desktop |
| **Android Kiosk App** | **Shared Android tablet / device** | **Multiple employees at one location** | **Face recognition (no login)** | **Factory gate, office entrance, site office** |
| **Sales Face Mapping** | **Mobile or approved device** | **Sales personnel only** | **Face map verification + GPS** | **Field sales, client visits, territory coverage** |

**Integration Rule:** Kiosk and sales face-mapping attendance records must use the same shift, grace, late-mark, OT, and payable-days rules defined in this document.

| Step | Action | System Behaviour |
| --- | --- | --- |
| 1 | Employee stands at kiosk | Camera activates; face scan starts |
| 2 | Face matched to employee | Display employee name + last punch status |
| 3 | Employee confirms punch | Record punch in or punch out with timestamp |
| 4 | Feedback shown | Success / failure message; return to scan screen for next employee |
| 5 | Sync | Attendance sent to HRMS; audit log with kiosk device ID |

### Kiosk Business Rules

| Case | Rule |
| --- | --- |
| 1 | One kiosk device may serve unlimited enrolled employees at that location |
| 2 | Employee must have face enrolled before kiosk attendance is allowed |
| 3 | Kiosk punch applies branch / location attendance policy automatically |
| 4 | Cross-day shift rules (BR-ATT-001) apply to kiosk punches same as mobile |
| 5 | Failed face match shall not create attendance; log attempt for audit |
| 6 | Offline punches queue locally and sync in order when connectivity restores |

### Kiosk vs Employee Mobile App

| Aspect | Kiosk App | Employee Mobile App |
| --- | --- | --- |
| Login | No employee login | Secure employee login |
| Device | Shared, fixed at location | Personal device |
| Users per device | Multiple employees | Single employee |
| Primary ID | Face recognition | Login + optional face/GPS |
| Self-service | Attendance only | Leave, payslip, profile, etc. |

## Sales Personnel Face Mapping

### Purpose

Sales personnel mark attendance through **face mapping** — a enrolled face profile linked to the sales employee record — combined with **GPS-tagged field attendance** for client visit and territory compliance.

### Sales Face Mapping Configuration

| Configuration | Options |
| --- | --- |
| Applicable Designation / Category | Sales / Field Sales / Business Development (configurable) |
| Face Enrollment | Mandatory for sales attendance via face map |
| Attendance Channel | Sales mobile app and/or approved kiosk |
| GPS Required | Yes — for field attendance |
| Geo-Fence | Optional per territory / client site |
| Face Match Threshold | Configurable score (tenant-level) |
| Punch Types | Punch In / Punch Out |
| Visit Tagging | Optional client / territory tag on punch |

### Sales Face Mapping Policy Master

| Case | Employee Type | Attendance Method | GPS | Payroll Action |
| --- | --- | --- | --- | --- |
| 1 | Sales Staff | Face map + mobile GPS | Required | Standard attendance rules |
| 2 | Sales Staff | Face map at kiosk (office start/end) | Kiosk location | Standard attendance rules |
| 3 | Sales Worker | Face map + field GPS | Required | Worker payable-days rules |
| 4 | Sales (exempt geo) | Face map only | Optional override | Per HR policy |

### Face Map Lifecycle

| Stage | Description |
| --- | --- |
| Enrollment | HR or employee enrolls face; system stores face map linked to employee ID |
| Verification | On punch, live face matched against stored face map |
| Re-enrollment | Required on significant appearance change or failed match threshold |
| Audit | All match scores, images (if policy allows), GPS coordinates logged |

### Sales Attendance Integration Rules

| Rule | Description |
| --- | --- |
| BR-SALES-001 | Only employees with Sales designation/category may use sales face-mapping policy |
| BR-SALES-002 | Face map must exist before first sales face attendance is accepted |
| BR-SALES-003 | GPS coordinates must be captured for mobile field punches unless exempted |
| BR-SALES-004 | Sales attendance feeds same late-mark, half-day, and payable-days engine as other modes |
| BR-SALES-005 | Client / territory tags are optional metadata for MIS reports, not payroll divisor |

### Example — Sales Field Day

| Time | Event | Capture |
| --- | --- | --- |
| 09:00 | Start day | Face map verify + GPS (office) |
| 11:30 | Client visit | Face map verify + GPS (client site) |
| 18:00 | End day | Face map verify + GPS (last location) |

Payroll uses present days and applicable sales attendance policy; visit tags appear in sales compliance reports.
